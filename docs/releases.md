# Releases

## Publish a version

1. Update `version` in `Cargo.toml` (then run `cargo build` to update `Cargo.lock`) and merge it into `main`.
2. Tag the merged commit with the same version and push the tag:

   ```sh
   git switch main && git pull
   git tag v0.1.0
   git push origin v0.1.0
   ```

The [Release workflow](../.github/workflows/release.yml) builds the archives for Windows, macOS and Linux and publishes them as a GitHub release, with their checksums (`SHA256SUMS.txt`). It fails if the tag does not match the version of `Cargo.toml`.

## What an archive holds

- the executable (`exile-market` or `exile-market.exe`) and `README.md`;
- `LICENSE`, the GNU General Public License;
- `THIRD-PARTY-LICENSES`, the licenses of the libraries built into the executable, generated by `cargo-about` (`about.toml`, `about.hbs`);
- under `assets/`, at the paths of the repository: `NOTICE.md`, `game-data/NOTICE.md`, the licenses of the fonts (`fonts/ofl-*.txt`) and of the icons (`icons/isc-lucide.txt`). A new embedded file under another license adds its text to the `Package` step of the workflow.

## The licenses of the dependencies

The workflow runs `cargo deny check licenses` first (`deny.toml`), and `cargo about` refuses the same licenses (`accepted` in `about.toml`, kept the same): a dependency under a license not listed stops the build, on the pull request that changes `Cargo.lock` too. Before adding a license to both lists, read it and check that it is compatible with `GPL-3.0-or-later`.
